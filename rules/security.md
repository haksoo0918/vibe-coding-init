# 보안 및 데이터 보호 규칙 (Security & Data Protection Rules)

본 문서는 프로젝트 개발 및 배포 과정에서 민감한 데이터의 유출을 막고, 시스템 파괴적 행위 및 보안 위협을 예방하기 위한 규칙을 정의합니다.

---

## 1. 민감 정보 및 자격 증명 보호

1. **하드코딩 절대 금지**:
   - API 키, 시크릿 키(Secret Key), 데이터베이스 비밀번호, 인증 토큰, 개인키(PEM 파일 등)는 절대 소스 코드에 하드코딩하지 않습니다.
   - 예시 파일이나 템플릿(예: `.env.example`) 작성 시에는 반드시 더미 값(예: `YOUR_API_KEY_HERE`)만 사용합니다.
2. **환경 변수 파일 관리**:
   - 실제 자격 증명이 담긴 `.env`, `.env.local`, `credentials.json` 등의 파일은 `.gitignore`에 등록하여 Git 추적 대상에서 제외합니다.
   - 프로젝트 설정 시 필수 환경 변수 목록과 설명을 기록한 `.env.example`을 제공합니다.
3. **노출된 자격 증명 즉시 폐기**:
   - 실수로 자격 증명이 Git 커밋 히스토리에 포함된 경우, 즉시 해당 키를 무효화(Revoke)하고 재발급받아야 합니다.

---

## 2. 파괴적 작업 방지 (Accidental Data Loss Prevention)

1. **사전 확인 및 동의 필수**:
   - 데이터 손실이나 영구적인 시스템 변경을 초래할 수 있는 명령어는 실행 전 반드시 사용자에게 위험성을 알리고 명시적인 확인을 받습니다.
2. **주의 대상 작업**:
   - 데이터베이스: `DROP TABLE`, `DROP DATABASE`, `TRUNCATE`, 조건절 없는 `DELETE`/`UPDATE`
   - 파일 시스템: 대량 파일 삭제(`rm -rf`, `Remove-Item -Recurse -Force`), 작업 디렉토리 외부 파일 변경
   - 클라우드 인프라: 스토리지 버킷 삭제, 데이터셋 삭제, 인프라 자원 삭제 명령
3. **백업 및 복구 고려**:
   - 중요한 스키마 마이그레이션이나 대규모 데이터 변경 작업 전에는 백업 방안을 먼저 확인합니다.

---

## 3. 의존성 및 패키지 보안

1. **공식/검증된 패키지 사용**:
   - 검증되지 않은 서드파티 패키지나 타이포스쿼팅(유사 철자 악성 패키지)에 주의합니다.
2. **취약점 점검**:
   - 패키지 매니저의 보안 점검 도구(`npm audit`, `pnpm audit`, `pip-audit` 등)를 주기적으로 활용하여 알려진 취약점을 점검합니다.
3. **최소 권한 원칙**:
   - 배포 환경, 서비스 계정, 클라우드 권한 부여 시 작업에 꼭 필요한 최소한의 권한(Least Privilege)만 부여합니다.
