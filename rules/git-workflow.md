# Git 워크플로우 및 커밋 규칙 (Git Workflow & Commit Rules)

본 문서는 프로젝트의 Git 브랜치 운용 방식, 커밋 메시지 작성 규칙, 그리고 사용자 요청 시 수행하는 `main` 브랜치 머지 및 원격 저장소 푸시 절차를 정의합니다.

---

## 1. 브랜치 전략 및 운용 원칙

프로젝트는 **개발용 `dev` 브랜치**와 **배포용 `main` 브랜치**를 엄격히 분리하여 운용합니다.

```text
[feature/xxx] (필요 시)
      │
      ▼
   [ dev ]  ◄── 기본 작업 브랜치 (모든 일상 개발 및 자율 커밋 진행 후 유지)
      │
      │ (★ 오직 사용자가 명시적으로 요청했을 때만 실행!)
      ▼
   [ main ] ◄── 안정화된 배포 브랜치 (CHANGELOG 기록 후 머지 및 GitHub 원격 푸시)
```

### 1.1 기본 작업 브랜치 (`dev` 유지 원칙)
- **모든 일상적인 개발 작업과 커밋은 `dev` 브랜치에서 진행하며 머무릅니다.**
- 서브 에이전트의 작업이 완료되고 테스트/린트를 통과하면 메인 에이전트가 `dev` 브랜치에 자율적으로 커밋합니다.
- **단위 작업이 끝났다고 해서 에이전트가 알아서 `main`으로 머지하지 않습니다.**

### 1.2 `main` 머지 및 원격 푸시 절차 (사용자 명시적 요청 시)
- `main` 브랜치 머지는 **사용자가 "main에 머지해줘", "배포해줘", "푸시해줘" 등 명시적으로 요청했을 때만** 수행합니다.
- **수행 단계**:
  1. `dev` 브랜치의 최종 빌드, 테스트 및 린트 검증 상태 확인
  2. `CHANGELOG.md` 파일에 신규 버전 번호(Semantic Versioning), 릴리즈 일자, 주요 변경 내역(추가/수정/제거 등) 작성
  3. `CHANGELOG.md` 변경 사항을 `dev` 브랜치에 커밋 (예: `문서: v1.1.0 릴리즈 CHANGELOG 업데이트`)
  4. `main` 브랜치로 전환 후 `dev` 브랜치 병합:
     ```bash
     git checkout main
     git merge dev
     ```
  5. **원격 저장소(GitHub 등) 푸시**:
     - 원격 저장소(`origin`)가 연결되어 있는 경우, `main` 브랜치와 `dev` 브랜치를 원격에 푸시합니다:
     ```bash
     git push origin main
     git push origin dev
     ```
  6. 완료 후 다시 `dev` 브랜치로 복귀하여 다음 개발 준비를 마칩니다:
     ```bash
     git checkout dev
     ```

## 2. 에이전트 자율 커밋 원칙 (Auto Commit in dev)

- `dev` 브랜치에서 작업할 때, 메인 에이전트는 서브 에이전트의 작업 단위가 완료될 때마다 **알아서 자율적으로 `dev`에 커밋을 진행**합니다.
- 아래의 한글 커밋 태그 컨벤션에 맞춰 명확하고 일관된 메시지를 기록합니다.

---

## 3. 한글 커밋 메시지 컨벤션 (Commit Convention)

커밋 메시지는 작업 의도를 명확히 파악할 수 있도록 **한국어 커밋 태그** 형식을 준수합니다.

### 기본 형식

```text
태그: 변경 요약 내용 (50자 이내, 명확한 한글 서술)

- 필요 시 상세 변경 이유나 배경 설명 작성 (선택 사항)
- 여러 항목일 경우 불릿 기호(-)를 활용
```

### 커밋 태그 목록

| 태그 | 용도 및 설명 | 예시 |
| :--- | :--- | :--- |
| **기능** | 새로운 기능 추가 | `기능: 소셜 로그인(구글/카카오) 연동` |
| **수정** | 버그 및 오류 수정 | `수정: 세션 만료 후 재로그인 리다이렉트 오류 해결` |
| **테스트** | 테스트 코드 추가 또는 기존 테스트 보완 (TDD) | `테스트: 사용자 세션 만료 검증 단위 테스트 추가` |
| **문서** | 문서 생성 및 수정 (PRD, CHANGELOG, 가이드 등) | `문서: v1.0.0 릴리즈 CHANGELOG 작성` |
| **리팩토링** | 기능 변경 없는 코드 구조 및 성능 개선 | `리팩토링: 데이터베이스 쿼리 중복 로직 함수화` |
| **스타일** | 코드 포맷팅, 세미콜론, 들여쓰기 등 서식 수정 | `스타일: ESLint 및 Prettier 포맷 적용` |
| **환경** | 빌드 설정, 의존성 패키지 변경, CI/CD 스크립트 | `환경: TailwindCSS 및 PostCSS 설정 파일 추가` |
| **제거** | 미사용 코드, 파일 또는 기능 삭제 | `제거: 더 이상 사용하지 않는 레거시 API 유틸 삭제` |

---

## 4. 민감 파일 커밋 방지
- 커밋 전 `.env`, 개인 API 키, 로그 파일, 빌드 결과물(`dist/`, `build/`, `node_modules/`)이 스테이징되지 않도록 `.gitignore`를 철저히 확인합니다.
