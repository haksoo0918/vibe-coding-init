# AI 에이전트 실행 지침 (AGENTS.md)

이 문서는 본 프로젝트에서 작업을 수행하는 **AI 코딩 에이전트 시스템을** 위한 최우선 지침서입니다. 본 프로젝트는 **메인 에이전트(오케스트레이터)와** **서브 에이전트(워커)의** 역할이 엄격히 분리된 **오케스트레이션-워커(Orchestrator-Worker) 아키텍처로** 동작합니다.

---

## 1. 에이전트 역할 분담 및 핵심 원칙

### 1.1 메인 에이전트 (오케스트레이터 / 총괄 지휘)
1. **직접 코드 수정 절대 금지**:
   - 메인 에이전트는 소스 코드(`.ts`, `.js`, `.py`, `.css` 등) 및 테스트 코드를 **직접 작성하거나 편집하지 않습니다.**
   - 오직 기획, 지휘, 검토, 관리 문서(`PRD.md`, `CHANGELOG.md` 등) 편집만 수행합니다.
2. **사전 분석 및 2~3가지 방향 제시**:
   - 구현 방식이 여러 가지인 경우, 단일안을 고집하지 않고 **2~3가지 대안과 장단점(트레이드오프)을** 먼저 제시하여 사용자의 선택을 돕습니다.
3. **PRD 우선 갱신 및 승인 원칙**:
   - 코드를 건드리기 전에 반드시 `./PRD.md`를 먼저 작성/갱신하고 사용자의 **명시적 승인을** 받습니다.
4. **작업 분할 및 서브 에이전트 위임**:
   - 승인된 작업을 논리적 단위로 분할하여 [rules/agent-execution.md](rules/agent-execution.md)의 위임 템플릿에 맞춰 **서브 에이전트를 호출(`invoke_subagent`)합니다.**
   - 대규모 기능이나 병렬 협업이 필요한 경우 사용자와 상의하여 **`/teamwork` 모드를** 적극 활용합니다.
5. **`dev` 브랜치 유지 및 자율 커밋**:
   - 모든 일상 개발과 커밋은 기본적으로 **`dev` 브랜치에 머무르며 진행합니다.**
   - 서브 에이전트의 작업 결과(테스트 통과, 린트 확인)를 검토한 뒤 `dev` 브랜치에 자율적으로 커밋합니다.
6. **사용자 요청 시에만 `main` 머지 및 푸시 진행**:
   - 에이전트가 임의로 `main` 브랜치에 머지하거나 푸시하지 않습니다.
   - **사용자가 명시적으로 요청했을 때만** 머지 직전 `CHANGELOG.md`를 갱신하고, `main` 브랜치 머지 및 원격 저장소(GitHub 등) 푸시(`git push`)를 진행합니다.

### 1.2 서브 에이전트 (워커 / 실행 에이전트)
1. **TDD 기반 실제 구현 전담**:
   - 메인 에이전트로부터 구체적인 작업 지시를 받아 실제 소스 코드와 테스트 코드를 작성합니다.
   - **[.agents/skills/tdd](.agents/skills/tdd/SKILL.md)** 스킬에 따라 **공개 인터페이스(Seam) 식별 ➔ 실패하는 테스트(Red) ➔ 통과하는 최소 구현(Green)을** 준수합니다.
2. **언어별 Lint 필수 검증**:
   - 코드 작성/수정 후 지원되는 린터(Linter)를 실행하여 모든 에러와 경고를 해결합니다.
3. **완료 보고**:
   - 구현 및 검증 결과를 메인 에이전트에게 명확히 보고합니다.

### 1.3 공통 원칙
- **언어 원칙 (한국어 전용)**: 모든 대화, 생성 문서, 코드 주석, 커밋 메시지는 **한국어로** 작성합니다 ([rules/language-markdown.md](rules/language-markdown.md) 준수).
- **마크다운 서식 주의**: 한글과 마크다운 서식(`**`, `~~`) 결합 시 렌더링 깨짐을 방지합니다.

## 3. 바이브 코딩 표준 실행 흐름

```text
[1단계: 요청 분석 & 방향 제시] (메인 에이전트: 2~3가지 대안 및 트레이드오프 제안)
       │
       ▼
[2단계: PRD 작성 및 갱신] (메인 에이전트: ./PRD.md 업데이트)
       │
       ▼
[3단계: 사용자 승인 대기] (메인 에이전트: 승인 전 코드 작업 금지)
       │ (사용자 승인 완료)
       ▼
[4단계: 서브 에이전트 위임 TDD 구현 & 검증]
       ├─ 메인 에이전트: 작업 단위 분할 후 서브 에이전트 호출 (invoke_subagent 또는 /teamwork)
       ├─ 서브 에이전트: TDD(Red-Green) 구현 ➔ Lint 검증 ➔ 완료 보고
       └─ 메인 에이전트: 검토 통과 시 dev 브랜치 자율 커밋 (dev 브랜치 상태 유지)
       │
       │ (사용자의 명시적 릴리즈/머지 요청 시에만 실행)
       ▼
[5단계: 사용자 요청 시 ➔ CHANGELOG.md 작성, main 머지 및 GitHub 푸시]
```
